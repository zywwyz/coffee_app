# Coffee Journal（咖啡日记）

Coffee Journal 是一款面向个人使用的 Android 本地咖啡记录 App。它可以记录连锁咖啡和个人豆子，在月历中用产品图或品牌 Logo 标记喝咖啡的日期，并生成月度、年度总结。

数据默认只保存在手机的 App 私有目录中；不需要账号、云服务或付费接口。

## 构建与安装

前置环境：

- JDK 17
- Android SDK Platform 36 与 Build Tools 36.0.0
- Android SDK Platform Tools（提供 `adb`）
- Android 6.0（API 23）或更高版本的手机

设置好 `JAVA_HOME` 与 `ANDROID_HOME` 后，在项目根目录执行：

```bash
./gradlew clean testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

可安装的调试 APK 位于：

```text
app/build/outputs/apk/debug/app-debug.apk
```

手机开启“开发者选项”和“USB 调试”，连接并授权后执行：

```bash
adb devices
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`-r` 会覆盖安装同一调试签名的旧版本并保留数据。若签名不同，Android 会要求先卸载旧版本；卸载会清除尚未备份的本地数据。

## 首次使用

首次启动会建立本地数据库，并加入瑞幸、Manner、M Stand、Peet's 和 % Arabica 五个连锁品牌。底部导航包含：

- **日记**：在月历查看记录，点击“记录一杯”新增当天咖啡。
- **豆库**：维护连锁品牌、连锁产品、烘焙品牌和个人豆子。
- **总结**：查看月度和年度杯数、消费、评分、偏好与趋势。
- **设置**：从页面右上角进入，导出备份或恢复备份。

## 记录一杯咖啡

在“日记”中选择连锁产品或个人豆子，再选择品牌与具体条目。只有“具体条目”必须选择；产品图片、评分、价格、冲煮方式和备注都可留空，不会阻止保存。

评分支持 0.5 星步进，实际支付金额精确到分。再次选择同一产品时，App 会参考上一次记录的实际价格。一天有多杯记录时，月历显示最后一杯的图片并标注 `×2`、`×3` 等数量；当天没有记录时显示普通日期数字。

月历图片依次使用：

1. 记录当时的产品图；
2. 记录当时的品牌 Logo；
3. 通用咖啡占位图。

记录会保存条目名称、产地、处理法、烘焙度、风味、产品图和品牌 Logo 的历史快照。以后修改豆库，不会改变旧记录。

## 连锁品牌与官网更新

在“豆库 > 连锁品牌”中可以新增或编辑品牌、Logo 和产品。官网更新只会在用户点击“更新该品牌”后运行，不会在后台自动请求网络。

当前仅为瑞幸和 M Stand 配置了公开网页解析；Manner、Peet's 中国和 % Arabica 没有稳定公开产品目录，建议使用截图导入或手工录入。App 不调用、不逆向也不依赖微信小程序私有接口。公开网页的地址、页面结构和产品信息可能随品牌调整，结果只能作为候选：必须在审阅页明确确认后才会写入本地豆库。

遇到离线、HTTP 错误或网页结构变化时，本地知识库保持不变。失败页提供：

- 重试官网更新；
- 上传截图并识别；
- 手工录入。

官网产品图片下载失败时，条目会标记为需要补图。记录该产品时会提示上传原始屏幕截图、选择已裁好的图片，或暂时跳过并使用品牌 Logo。

## 截图 OCR 与裁剪

可以直接选择手机原始全屏截图，无需事先裁成合适大小。App 在本机读取截图、进行中文文字识别，并提供可调整的裁剪框。请在确认页校对产品名、价格等候选字段；低置信度或识别失败时可手工填写。只有明确确认后，裁剪图和信息才会进入豆库。

原始截图可能包含通知、账号名、订单号等敏感内容。App 代码把截图像素交给设备上的 Google ML Kit 文字识别组件，本机得到识别文字并完成裁剪；没有把截图像素或识别结果上传到自建服务器、品牌官网或云端识别接口。原始截图不会复制到 App 的长期图片库，只有确认后的裁剪结果会保存。

需要注意：项目包含 Google ML Kit SDK。即使文字识别本身在设备上运行，该 SDK 仍可能通过 HTTPS 向 Google 发送有限的设备信息、应用信息，以及 API 使用量、性能和错误等诊断指标，用于维护和改进 SDK。这类诊断信息不同于截图像素和 OCR 识别文字；本 App 没有主动把后两者加入网络请求。因此不能把安装后的所有联网活动概括为“只有官网更新”。具体边界可查阅 Google 的 [ML Kit Terms & Privacy](https://developers.google.com/ml-kit/terms) 与 [Android data disclosure](https://developers.google.com/ml-kit/android-data-disclosure)。

## 个人豆库

在“豆库 > 我的豆子”中新增烘焙品牌，再手工录入豆子。可以记录产地、处理法、烘焙度、风味、购买/烘焙日期、包装图片和建议冲煮方式，并按在用、喝完或归档状态筛选。个人豆库不依赖网络。

## 月历与月度/年度总结

“日记”月历显示当月杯数、消费合计和平均评分；点击有记录的日期可查看当天详情。“总结”页支持月度与年度切换，包含消费与评分趋势、品牌消费占比、常喝品牌/产品/豆子/冲煮方式，以及最高和最低评分记录。没有填写价格或评分的记录仍会计入杯数，但不会虚构金额或评分。

## 备份与恢复

在“设置”中选择“导出备份”，通过 Android 系统文件选择器保存 ZIP。备份包含数据库以及被记录、豆库和 Logo 引用的本地图片，并带有完整性校验信息。

恢复时选择之前的 ZIP。App 会先在临时区域校验格式、校验和、数据库完整性和图片，再展示备份版本、时间和内容摘要。只有再次确认后才会用备份完整替换当前数据；校验或恢复失败时，现有数据保持不变。

备份 ZIP **没有加密**，可能包含咖啡记录、备注和图片。请保存在可信位置，不要公开分享。恢复会覆盖当前全部数据，建议恢复前先导出一份当前备份。

App 已明确排除 Android 系统云备份和设备迁移中的全部私有数据库、文件、偏好与外部私有文件。跨设备保留数据应使用设置页中由你主动导出的 ZIP。

> 卸载 App 或清除应用数据会删除 App 私有目录中的记录和图片。卸载前务必先把备份导出到“下载”、电脑或其他 App 外部位置。

## 离线行为与隐私

日常记录、个人豆库、月历、总结、截图裁剪和备份恢复的功能核心均在本机运行。App 自身只有在你手动触发公开官网更新或下载官方产品图片时请求产品内容；此外，上述 ML Kit SDK 可能联网发送诊断指标。Manifest 不申请通讯录、定位、相机或宽泛存储权限；选图与备份使用 Android 系统选择器授予的单个文件访问权。

App 没有账号、广告、自建服务器、云同步、后台官网更新，也没有另行接入广告或用户行为分析 SDK。咖啡记录、备注、截图像素、OCR 文字和裁剪图片留在本机，除非你主动通过系统文件选择器导出备份；Google ML Kit 的有限诊断通信是前述边界的例外。

## 发布前验证

无真机时可以运行 Robolectric 本地跨层替代覆盖，并编译 instrumentation 测试 APK：

```bash
./gradlew clean testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest assembleRelease
```

连接真机后再执行：

```bash
./gradlew connectedDebugAndroidTest
```

真机验收应覆盖：离线记录、截图 OCR/裁剪、自定义品牌与 Logo、个人豆子、月/年总结，以及备份后恢复全部记录和图片。

Robolectric 只验证本地进程内的 MainActivity、导航、Room、ViewModel 和 Compose UI 链路，不能替代 instrumentation 与真机验收，也不能证明 Android 系统文件选择器、设备上的 OCR 模型和完整备份恢复在具体手机上正常工作。

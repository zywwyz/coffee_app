# 手动连锁咖啡豆库改版设计

日期：2026-08-16  
状态：用户已确认，等待实施

## 1. 背景与目标

当前连锁品牌卡片信息密度低，单个品牌占用空间过大；官网产品更新和截图 OCR 在真机上不可用，也给个人离线使用带来不必要的网络、解析和识别复杂度。

本次改版目标是把连锁豆库收敛为稳定、完全手动、离线优先的个人产品库：

- 品牌首页以紧凑 Logo 网格展示。
- 品牌产品页以实拍图片网格展示。
- 品牌和产品均由用户手动维护。
- 当天记录可以快速新建产品，并自动选中新产品。
- 删除官网更新、截图 OCR 和裁剪功能。
- 保留历史饮用记录和旧备份兼容性。

## 2. 范围

### 2.1 本次包含

- 连锁品牌页、品牌产品子页面与导航。
- 12 个内置连锁品牌及本地 Logo。
- 自定义品牌的名称和 Logo 新增、编辑。
- 连锁产品的名称、实拍图和三分类新增、编辑。
- 记录页快速新增产品并自动选中。
- 旧产品分类迁移、Room schema 升级与备份兼容。
- 官网更新、截图 OCR、识别审核和裁剪代码移除。
- 无其他联网需求时移除网络权限和相关依赖。

### 2.2 本次不包含

- 自动或后台更新品牌和产品。
- 微信小程序私有接口。
- 云同步、账号或多人共享。
- 品牌门店查询、门店数展示或动态排名更新。
- 品牌或产品批量导入。
- 品牌、产品删除行为的新增设计。
- 个人咖啡豆页面的结构性改版。

## 3. 初始品牌名单

预置名单采用 2025 年底中国大陆在营门店数量作为入选口径。窗口店、便利店寄生店、餐车和速取窗口计入行业统计，但 App 不展示门店数或排名。

按门店规模排序的 Top 10：

1. 瑞幸咖啡
2. 库迪咖啡
3. NOWWA 挪瓦咖啡
4. 幸运咖
5. 星巴克
6. 肯悦咖啡
7. MANNER
8. 沪咖
9. Tims 天好咖啡
10. M Stand

额外保留用户此前指定的：

11. Peet's
12. %Arabica

名单依据以 2025 年末 GeoQData 和同期行业门店跟踪为基准。该数据只决定首次安装时的品牌顺序，不作为 App 内长期维护的数据字段。

每个预置品牌使用随 APK 打包的真实品牌 Logo。资产应优先取自品牌官方公开材料，记录来源和获取日期，并保留商标归属说明。不得在运行时联网下载 Logo。

所有 12 个 Logo 必须作为真实图片资源进入源码和 APK；不得使用远程 URL、favicon 服务、文字首字母或仅在预览网页有效的占位图。构建测试需要逐个验证资源存在、可解码且不是同一张通用占位图。

## 4. 信息架构与页面

### 4.0 应用名称与根页面

- 手机桌面、系统应用列表和安装信息中的 App 名称统一改为“咖啡日历”。
- 删除系统原生 `Coffee Journal` ActionBar，也不增加全局 Compose 顶栏。
- 三个底部 Tab 各自渲染自己的页面标题和首屏内容。
- 第一个底部 Tab 名称从“日记”改为“咖啡日历”；豆库和总结名称保持不变。
- 日记根页面标题为“咖啡日历”，豆库根页面标题为“我的咖啡豆库”，总结根页面标题为“咖啡回顾”。
- 设置入口放进各根页面自己的标题行；设置页提供自己的返回入口，不依赖全局顶栏。

### 4.1 连锁品牌首页

- 保留豆库中的“连锁品牌”和个人豆库分区；本次仅改造连锁品牌部分。
- 连锁品牌使用方案 A：每行三张方形品牌卡。
- 卡片只显示 Logo 和品牌名。
- 不显示门店数、排名、产品数、更新时间、更新状态或官网入口。
- 预置品牌使用固定名单顺序；自定义品牌排列在预置品牌之后。
- 网格末尾提供“新增品牌”卡片。
- 点击品牌卡进入独立品牌产品页。

### 4.2 品牌产品页

- 顶部提供返回、品牌 Logo、品牌名和“编辑品牌”。
- 产品以双列图片卡展示。
- 卡片显示产品实拍图、产品名称和类型标签。
- 支持“全部／黑咖／果咖／奶咖”筛选。
- 仅在确有旧迁移数据时显示“待分类”筛选或标记。
- 没有实拍图时，在中性背景上使用品牌 Logo 占位。
- 页面提供“添加产品”入口。
- 点击现有产品进入产品编辑页。
- 空品牌显示明确空状态及“添加第一个产品”。

### 4.3 品牌编辑

- 自定义品牌新增时，品牌名称和 Logo 均必填。
- Logo 从系统相册／文件选择器导入，复制到 App 私有图片存储。
- 品牌详情页可以修改品牌名称和 Logo。
- 预置品牌允许用户更换 Logo；后续启动不得用内置资源覆盖用户修改。
- 对已有预置品牌，仅在 `logoAssetId` 为空时补充内置 Logo。

### 4.4 Activity 顶部窗口

真机截图确认三个底部根 Tab 都被系统原生 `Coffee Journal` ActionBar 遮挡。根因是 Manifest 未为 `MainActivity` 指定 NoActionBar 窗口主题，系统根据应用 label 额外绘制了原生 ActionBar，而 App 内容已经由 Compose 自己完整管理。

- 为应用指定明确的 NoActionBar XML 主题，保留现有 Compose `CoffeeTheme` 作为内容主题。
- 不在日记、豆库、总结三个页面分别增加补丁式顶部 padding。
- 系统状态栏、Compose 内容和底部导航栏各自只占用一次安全区域。
- 三个根 Tab 的页面标题及第一行内容必须完整可见。
- 设置页和品牌产品子页面也不得重新出现原生 ActionBar。

### 4.5 月历显示模式

- “咖啡日历”页面标题下方提供两个互斥选项：`品牌`／`咖啡`。
- 默认使用“咖啡”模式；用户切换后通过本地偏好保存，下次启动继续使用上次选择。
- “品牌”模式：有记录的日期只显示代表记录的品牌 Logo；品牌 Logo 缺失时使用通用咖啡占位图。
- “咖啡”模式：优先显示代表记录的产品实拍图，无实拍图时回退到品牌 Logo，再回退到通用咖啡占位图。
- 同一天多杯继续选择时间最新（相同时间按稳定 ID）的代表记录，并显示 `×N`；本次不增加多图拼贴。
- 切换只改变月历渲染，不修改饮用记录、目录、草稿或统计数据。

## 5. 产品模型与编辑

### 5.1 字段

- 产品名称：必填，去除首尾空白。
- 产品类型：必填，只允许 `黑咖`、`果咖`、`奶咖`。
- 产品实拍图：可选。
- 同一品牌内产品名称规范化后必须唯一。

“待分类”只用于承载无法自动映射的旧数据，不是新建或编辑时可选择的第四种类型。

### 5.2 图片行为

- 使用系统相册／文件选择器选择原图。
- 不执行 OCR、截图识别或手动裁剪。
- 导入后复制原始图片到 App 私有存储。
- 卡片渲染使用居中裁切，不修改保存的原始文件。
- 编辑时可替换或移除图片。
- 移除产品实拍图后回退到当前品牌 Logo。
- 图片导入失败时保留原值并显示可重试错误，不产生悬空引用。

### 5.3 历史不可变性

编辑当前豆库产品不得重写既有饮用记录中的名称、图片或品牌 Logo 快照。只有用户编辑某条饮用记录并明确更换产品时，才按现有规则生成新的记录快照。

## 6. 新增产品流程

### 6.1 从豆库新增

品牌产品页 → 添加产品 → 填写名称和类型、可选照片 → 保存 → 返回品牌产品页并显示新产品。

### 6.2 从当天记录快速新增

记录页选择品牌后，在产品选择区域提供“添加新产品”：

1. 打开与豆库共用的产品编辑器。
2. 新建产品写入目录 Repository。
3. 保存成功后返回原记录表单。
4. 通过现有 `JournalViewModel.selectItem(newItemId)` 选择新产品。
5. 保留用户已填写的饮用时间、评分、价格、冲煮和备注。

取消或保存失败时返回原记录表单，不改变当前产品选择和已填写字段。

## 7. 旧数据迁移

- Room schema 升级到 v3，为产品增加受约束的产品类型。
- v2→v3 迁移按规范化后的旧 `category`／相关字段映射：
  - 明确的美式、浓缩、冷萃等映射为黑咖。
  - 明确的水果、果汁、果味气泡等映射为果咖。
  - 明确的拿铁、澳白、卡布、奶／乳等映射为奶咖。
  - 无法可靠判断的映射为内部 `PENDING`／待分类状态。
- 新增和编辑产品时领域校验拒绝 `PENDING`。
- 待分类旧产品仍可见，编辑保存时必须选择三种正式类型之一。
- 迁移不得改变记录快照、草稿引用和图片引用。

内置品牌初始化必须幂等：补充缺失的七个 Top 10 品牌，不重复创建现有五个品牌，不覆盖用户已修改的名称或 Logo。

## 8. 删除旧功能

删除所有用户可达入口和不再使用的实现：

- 官网更新按钮、状态、失败重试和候选确认。
- 公开官网适配器、HTML／JSON 解析、网络传输与官网图片下载。
- 截图 OCR、识别结果审核、截图导入会话和裁剪交互。
- ML Kit OCR 与仅服务上述功能的 OkHttp 等依赖。
- 相关 ViewModel、状态模型、测试桩和文案。

为兼容严格备份 schema，旧 `catalog_updates` 表暂时保留但不再由生产业务读写。若移除所有运行时联网路径，应同时删除 `INTERNET` 权限并更新 README 隐私说明。

## 9. 备份与恢复

- 新备份导出当前 v3 Room 数据库和全部被引用图片。
- 恢复继续接受受支持的 v1、v2 和 v3 备份。
- v1／v2 数据恢复到 staging 后执行受信 Room 迁移，再做 v3 schema、域约束、图片和引用校验。
- v3 的 schema 白名单、identity hash、列约束和产品类型域必须加入校验。
- 恢复过程继续遵守现有全局备份锁、图片变更协调锁、取消边界和原子事务约束。

## 10. 错误与空状态

- 品牌 Logo 导入失败：不保存品牌，保留编辑输入并允许重试。
- 产品图片导入失败：不覆盖旧图；新产品仍可移除图片后使用品牌 Logo 保存。
- 产品重名：在名称字段显示同品牌重名提示。
- 目录写入失败：记录页不自动选中，不清空用户已填写记录内容。
- 待分类产品：明确提示“请编辑并选择黑咖、果咖或奶咖”。
- 品牌无产品：展示空状态，不伪造产品。

## 11. 验收标准

### UI 与导航

- 12 个预置品牌均有真实本地 Logo。
- 12 个 Logo 资源均可从 APK 解码，品牌之间不共享通用占位资源；离线启动仍全部显示。
- 连锁品牌首页为三列卡片且没有任何门店数／排名。
- 点击品牌进入独立双列产品页，返回行为正确。
- 小屏幕和较长品牌名下无溢出，网格可滚动。
- Debug APK 真机启动后不显示系统原生 `Coffee Journal` ActionBar。
- 系统和桌面显示的 App 名称为“咖啡日历”，第一个底部 Tab 也显示“咖啡日历”。
- App 不存在全局顶栏；三个根 Tab 各自显示自己的页面标题和设置入口。
- 日记、豆库、总结三个根 Tab 的标题和首屏顶部信息均不被状态栏或其他顶栏遮挡。
- 自动化测试验证 `MainActivity` 不创建原生 ActionBar，并验证三个根页面顶部语义节点处于可见区域。
- 月历标题下方显示“品牌／咖啡”双选切换，默认“咖啡”且切换值可跨进程恢复。
- “品牌”模式始终显示品牌 Logo；“咖啡”模式按产品实拍图 → 品牌 Logo → 通用图回退。
- 切换模式不改变同日代表记录和 `×N` 计数，也不触发任何数据库记录写入。

### CRUD 与记录联动

- 可新增、编辑自定义品牌名称和 Logo。
- 可新增、编辑产品名称、类型和照片。
- 产品无照片时展示品牌 Logo。
- 记录页快速新增成功后自动选择新产品并保留其他草稿字段。
- 编辑产品不改变历史记录快照。

### 迁移与备份

- v2→v3 合法数据无损迁移，三类及待分类映射正确。
- 迁移异常时 Room 不打开半迁移数据库。
- v1／v2／v3 合法备份可恢复到 v3。
- 非法 schema、非法产品类型、缺图和哈希不匹配仍在写入前被拒绝。

### 移除与离线

- UI 不存在官网更新、截图识别或裁剪入口。
- 生产代码不包含可达官网更新和 OCR 流程。
- 不再存在仅用于旧功能的依赖和网络权限。
- 飞行模式下品牌、产品、记录、统计和备份核心流程可用。

## 12. 实施与审查策略

- 主 Agent 负责最终数据模型、迁移和跨页面状态方案。
- 明确编码任务交由单一 implementer，避免多 Agent 同时修改数据库和目录核心文件。
- 先写迁移、Repository 和 UI 行为红灯测试，再实施。
- UI／业务逻辑完成后进行普通 reviewer 审查。
- Room v3、旧备份恢复、图片引用和数据一致性由 critical_reviewer 专项审查。
- 最终按 targeted tests → 模块测试 → lint/build → 完整发布矩阵逐级验证。

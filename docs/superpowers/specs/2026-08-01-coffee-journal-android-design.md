# 咖啡日记 Android App 设计规格

日期：2026-08-01

## 1. 产品目标

为一名中国大陆 Android 用户开发一款免费、无需账号、以本地数据为主的个人咖啡日记 App。用户应能在约十秒内记录一杯咖啡，并通过月历、月度总结和年度总结回顾自己的品牌与产品偏好、评分变化和实际消费。

首版只服务个人使用，不上架应用商店，交付形式为可侧载安装的 APK。核心功能离线可用；只有用户主动更新品牌产品或导入网页图片时才联网。

## 2. 范围

### 2.1 首版包含

- Android 原生 App。
- 月历式咖啡日记和每日多杯记录。
- 快速记录：选择连锁产品或个人豆子后自动补全知识库信息。
- 1–5 星评分，支持半星。
- 实际支付金额，并记住同一产品上次填写的价格。
- 连锁产品知识库，首发支持瑞幸、Manner、M Stand、Peet's 和 % Arabica。
- 用户在 App 内新增连锁品牌、品牌 Logo 和产品。
- 个人豆库，按烘焙品牌分类，由用户手工维护具体豆款。
- 公开官网按品牌手动更新、更新差异确认、小程序截图本地识别、手工录入兜底。
- 月度与年度总结。
- 完整本地备份的导出与导入。

### 2.2 首版不包含

- 用户账号、云同步或多人共享。
- 后台自动更新或定时联网。
- 微信小程序私有接口、绕过鉴权或逆向抓取。
- 对外公开的数据服务。
- App 商店上架与付费基础设施。
- 根据产品名推测未公开的豆子产地、处理法或其他事实。

## 3. 产品原则

1. 快速优先：高频记录只要求选择对象、评分和实际价格。
2. 本地优先：日记、知识库、图片和统计均保存在设备中。
3. 历史不可篡改：每条饮用记录保存知识库信息与图片的当时快照。
4. 来源透明：联网获得的产品信息保存来源链接和获取时间；未知字段明确显示未知。
5. 用户确认：官网更新和截图识别的结果在写入前必须由用户确认。
6. 安全降级：图片、网络或解析失败不能阻塞记录咖啡。

## 4. 信息架构

底部导航包含三个主入口：

- 日记：月历首页、日期详情和快速记录。
- 豆库：连锁品牌、连锁产品、烘焙品牌和个人豆款。
- 总结：月度总结、年度总结和年份切换。

设置入口包含备份导入导出、图片缓存管理、数据来源说明和应用信息。

## 5. 日记与记录体验

### 5.1 月历首页

- 默认展示当前月份。
- 没有咖啡记录的日期显示正常数字。
- 有记录的日期显示当天代表咖啡的真实产品图片。
- 同一天多杯时，展示当天最后一杯的图片和 `×N` 数量角标。
- 点击日期打开当天的全部饮用记录。
- 月历下方展示本月杯数、总消费和平均评分。
- 主操作按钮为“记录一杯”。

图片显示优先级为：真实产品图、品牌 Logo、通用咖啡占位图。

### 5.2 快速记录

用户先选择来源：

1. 连锁产品：选择品牌和产品。
2. 个人豆子：选择烘焙品牌和豆款。

选择后自动带入知识库字段和图片。用户填写或确认：

- 饮用日期与时间，默认当前时间。
- 0.5–5 星评分。
- 冲煮方式，连锁产品默认使用知识库值，个人豆子默认带入该豆款上次选择。
- 实际支付金额，默认带入该产品上次记录的价格；个人豆子填写本杯估算成本并复用上次值。
- 可选备注。

保存成功后，新记录立即出现在月历和当天列表中，月度与年度统计同步重算。

### 5.3 产品缺图提示

官网图片下载失败时，产品仍可加入知识库，并以品牌 Logo 显示，同时标记为“待补充图片”。

用户第一次使用该产品创建饮用记录时，App 提示通过截图补图，并提供：

- 上传完整截图并自动识别、裁剪。
- 从相册选择已经裁好的图片。
- 暂时跳过，继续使用品牌 Logo。

补图成功后，裁剪图同时写入产品知识库和当前饮用记录。选择跳过不会阻塞记录；下次继续提示，除非用户勾选“不再提醒”。产品详情页始终保留手工补图入口。

## 6. 知识库

### 6.1 连锁品牌与产品

连锁品牌页默认展示五个首发品牌。每个品牌显示 Logo、产品数量、上次更新时间和更新入口。

用户可新增任意连锁品牌，并指定：

- 品牌名称与 Logo。
- 维护方式：公开网页更新或仅手工维护。
- 可选的公开产品页地址。

连锁产品可保存：

- 产品名称、分类和规格描述。
- 一张产品图片及其来源。
- 可公开确认的豆子产地、处理法、烘焙度和风味信息。
- 可选咖啡因信息与官方描述。
- 来源链接、最近获取时间、当前状态和信息完整度。
- 用户手工修正内容。

产品下架只改变状态，不删除条目和历史记录。

### 6.2 个人豆库

个人豆库按烘焙品牌分组。品牌保存名称和 Logo；每个豆款由用户手工录入：

- 豆款名称和包装图。
- 产地、处理法、烘焙度、风味描述。
- 可选购买日期、烘焙日期和备注。
- 状态：正在喝、已喝完或归档。

同一豆款只需录入一次，之后在快速记录中复用。

## 7. 品牌手动更新

### 7.1 数据来源策略

采用混合式按需更新：

- 对存在稳定公开产品页的品牌，开发独立来源适配器。
- 不稳定或无完整公开菜单的品牌使用截图导入或手工维护。
- App 不调用微信小程序私有接口。
- 用户只有点击某品牌的“更新”时才联网。

公开来源示例：

- [瑞幸公开产品页](https://www.lkcoffee.com/products)
- [M Stand 公开产品页示例](https://www.mstand.cn/productinfo/747751.html)
- [Manner 官网](https://www.manner-coffee.cn/)
- [Peet's 中国官网](https://www.peets.cn/m/)

### 7.2 更新流程

1. 用户点击品牌的“更新”。
2. 来源适配器读取公开页面并生成候选条目。
3. App 与本地知识库比较，标记新增、修改和疑似下架。
4. 用户逐项勾选，并查看字段级差异与来源。
5. 用户确认后，整批变化在单个数据库事务中写入。
6. 更新只影响知识库，不修改历史饮用快照。

### 7.3 截图导入

用户直接选择完整手机截图，无需预先裁剪。App 在设备本地完成：

1. 中文文字识别和价格候选提取。
2. 产品卡片与图片区域候选检测。
3. 多产品截图中的目标产品选择。
4. 可调整的图片裁剪框。
5. 产品名、价格和裁剪图的确认。

原始截图默认在导入完成后释放，不复制到 App 私有存储；只保存用户确认后的裁剪图。识别失败时允许手工框选图片并填写字段。

## 8. 图片规则

- 连锁产品优先使用公开官方产品图并保存来源链接。
- 小程序截图只保存用户确认的裁剪区域。
- 个人豆子使用拍照或相册中的包装图。
- 连锁品牌和烘焙品牌均可保存 Logo。
- 图片首次使用后复制到 App 私有目录，支持离线查看。
- 饮用记录引用独立快照图片；知识库换图不影响历史。
- 删除知识库图片前检查历史快照引用，避免破坏日记。

## 9. 月度与年度总结

### 9.1 月度总结

- 总消费、与上月的金额差、单杯平均价格。
- 最常喝品牌、产品、个人豆子和冲煮方式及次数。
- 最高分与最低分咖啡，可进入原始记录。
- 按周展示评分趋势和消费趋势。
- 品牌消费占比。

### 9.2 年度总结

- 全年总消费、月均消费和单杯平均价格。
- 十二个月消费曲线及最高、最低月份。
- 年度最常喝品牌、产品、豆子和冲煮方式。
- 年度最高分和评分最高的前五项。
- 各月平均评分变化。
- 切换年份查看往年总结。

### 9.3 统计规则

- 金额使用每条记录的实际支付金额。
- 个人豆子的金额表示用户手工填写的本杯估算成本；首版不根据豆袋价格和粉量自动推算。
- 同一天多杯分别计数。
- 未评分记录计入杯数和消费，但不进入评分均值。
- 删除或修改记录后立即重新计算。
- 并列第一时同时展示。
- 样本不足时只展示事实值，不生成误导性的趋势描述。

## 10. 技术架构

### 10.1 平台与组件

- Kotlin 原生 Android 应用。
- Jetpack Compose 构建 UI，单 Activity 和单向数据流。
- ViewModel 暴露页面状态。
- Repository 隔离数据库、网络适配器、OCR 和文件系统。
- Room/SQLite 保存结构化数据。
- App 私有文件目录保存图片。
- 内置中文 ML Kit 文本识别模型，避免运行时依赖 Google Play 服务下载。
- Android Storage Access Framework 负责备份文件的导出与导入。

参考：

- [Android 架构建议](https://developer.android.com/topic/architecture/recommendations)
- [Jetpack Compose](https://developer.android.com/compose)
- [Room](https://developer.android.com/training/data-storage/room)
- [ML Kit Android 中文文字识别](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)
- [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files)

### 10.2 模块边界

- `journal`：月历、日期详情、快速记录和草稿。
- `catalog`：品牌、产品、烘焙品牌和个人豆款。
- `importer`：官网来源适配器、差异计算、截图识别和裁剪。
- `insights`：月度与年度聚合计算。
- `backup`：数据与图片打包、校验和恢复。
- `core`：数据库、图片存储、网络、时间和通用 UI。

每个模块通过 Repository 接口访问数据；UI 不直接访问数据库、网络或文件系统。

## 11. 数据模型

核心实体：

- `Brand`：品牌类型、名称、Logo、本地维护方式、公开来源地址。
- `ChainProduct`：所属品牌、名称、分类、公开属性、当前图片、来源和状态。
- `RoasterBean`：所属烘焙品牌、名称、咖啡豆属性、包装图和状态。
- `DrinkRecord`：时间、来源类型、来源 ID、冲煮方式、评分、实际价格、备注和完整快照。
- `ImageAsset`：本地路径、类型、来源、校验值和创建时间。
- `CatalogUpdate`：品牌、获取时间、结果状态和错误摘要。
- `CatalogChange`：候选变更类型、字段差异和用户决定。
- `DraftRecord`：未完成记录表单。

金额以人民币分的整数保存，避免浮点误差。半星评分以 1–10 的整数保存并在界面除以二。时间保存为绝对时间与本地日期，确保月历和跨时区备份恢复一致。

饮用快照至少包含显示名称、品牌名称、豆子属性、图片资产引用和记录时的来源版本。快照与知识库当前值分离。

## 12. 备份与恢复

备份文件包含：

- 带格式版本号的数据文件。
- 所有被知识库或历史记录引用的本地图片。
- 清单和校验值。

导入流程先解包到临时目录，验证格式版本、文件清单和校验值，再使用数据库事务写入。任何校验或写入失败都保留原数据库不变。恢复成功后再清理临时文件。

## 13. 异常处理

- 官网不可访问：保留本地数据，显示错误和上次成功更新时间。
- 页面格式变化：停止该品牌导入，改用截图或手工录入。
- OCR 不确定：高亮低置信度字段，等待用户确认。
- 疑似重复：允许合并、保留两项或取消。
- 官方图下载失败：使用品牌 Logo，标记待补图，并在首次记录时提示截图补图。
- 产品疑似下架：只标记，不删除。
- 备份损坏或不兼容：导入前终止，不修改现有数据。
- 保存中断：保留表单草稿。
- 批量更新失败：事务回滚，知识库保持更新前状态。

## 14. 测试与验收

### 14.1 自动化测试

- 月度与年度金额、排名、并列、未评分和平均值计算。
- Room DAO、约束、事务和数据库迁移。
- 饮用记录快照与知识库更新隔离。
- 重复产品检测和字段差异计算。
- 各品牌来源适配器使用保存的公开页面样本测试。
- 备份导出和导入往返测试，包括损坏文件。
- ViewModel 状态和关键 Compose 页面交互测试。

### 14.2 真机验收

- 常用路径在约十秒内完成一杯记录。
- 月历空日期显示数字，有记录显示真实产品图，缺图显示品牌 Logo，多杯显示角标。
- 更新知识库后，历史记录保持原名称、属性和图片。
- 截图可以识别中文产品名和价格，支持多产品选择与裁剪调整。
- 无网络时可以记录、浏览日记和查看总结。
- 导出备份后，在清空的测试安装中导入，记录、知识库和图片完整恢复。
- 官网更新、图片失败、OCR 失败和中断保存均按本规格安全降级。

## 15. 成功标准

首版完成时，应满足：

1. 用户可安装 APK，无需注册即可开始记录。
2. 日常记录主要路径约十秒内完成。
3. 月历正确使用产品图、品牌 Logo 和多杯角标。
4. 个人豆子与连锁产品均可复用知识库信息。
5. 五个首发品牌均可手工维护；公开来源可用的品牌支持按需更新。
6. 截图导入和产品缺图补图流程可用。
7. 月度与年度总结正确呈现偏好、评分和实际消费。
8. 完整备份可恢复全部记录与图片。
9. 任何联网、解析或识别失败都不会破坏本地数据或阻止手工记录。
